# Question spec v2 (Advisor design; authoritative)

Format for every question in QUESTIONS.md (Korean):
- ID, round, title
- 질문 (one clear Korean question sentence ending with "?")
- 왜 묻는가 (what it decides: named agents/skills/config keys/phases)
- 선택지 A-E (4-5 options; each option = one line label + one sentence consequence)
- 권장안 (option + reason + source) or "권장안 없음(창업자 판단)" with the reason
- 근거 (HF-REF-NN §x.y / file:line / F-NN from design-spec)
- 선행 질문 (dependencies) and 영향 (which later questions it changes)
- 답변 / 결정 기록 fields left blank: "답변: (미정)", "결정 ID: DEC-" 
AskUserQuestion allows max 4 options + automatic "Other". When a question has 5 options, mark which 4 go into the tool and state that the 5th is selectable as "Other".

## R1 범위와 용도 (answers gate everything)
Q01 에이전트 조직의 주된 용도
 A 설립 준비 지원 (사업계획서, 규정집, 책무구조도, 등록 서류)
 B 투자 운용 지원 (리서치, 투자 메모, 포트폴리오·리스크 분석, 사후 검토)
 C 운용사 전체 운영 체계 (투자·통제·운영·IR 상시 지원)
 D 단계 확장: A로 시작해 B, C 순서로 확장  [권장: 설립 로드맵이 약 8~9개월이고 첫 펀드 전에는 투자 운용 기능이 쓰이지 않음 HF-REF-05 표 4-2]
 E 교육·모의 운용 (실제 자금 없이 조직 운영 연습)
 영향: Q20, Q22, Q23, 단계 활성화
Q02 에이전트와 실제 인력의 관계
 A 보조형: 모든 직무를 사람이 맡고 에이전트는 초안·점검·기록만
 B 법정 직무만 사람 전담, 나머지 기능은 에이전트가 실행 직전 초안까지 수행
 C 가상 조직형: 에이전트가 전 기능 수행, 창업자는 승인만 (등록 후 법정 인력 요건과 충돌)
 D 채용 전에는 창업자 1인 + 에이전트, 채용 후 보조형(A)으로 전환  [권장: 현재 설립 전 단계 현실 + 등록 후 법정 요건 F-10]
 근거: HF-REF-05 표 4-1 (상근 투자운용인력 3명), HF-REF-06 §4.5 (준법감시인 겸직 금지), F-09
Q03 창업자(사용자)의 직책
 A 대표이사(CEO) 전담  B 대표이사 겸 CIO (흔한 형태, HF-REF-08 표 6-1)  C CIO 전담 (대표이사 별도 선임)  D 대주주·이사회 의장 (비상근, 경영 위임)
 권장안 없음(창업자 판단). 주의: B를 고르면 Q10의 A안이 사실상 CIO 보고가 됨. 준법감시인 직책은 운용 겸직 금지이므로 선택지에 없음 (HF-REF-06 §4.5).
Q04 Strategy C의 저장소 방식
 A 새 저장소에 CCGS 파일을 복사하고 독립 관리
 B 새 저장소 + CCGS를 upstream 원격으로 등록, 운영 기반 파일 경로를 유지해 UPGRADING.md의 A2(선택 체크아웃)·B(cherry-pick)로 수정 수신  [권장: F-15]
 C 현재 저장소 안의 별도 디렉터리
 D 현재 저장소 포크 후 게임 요소 제거 (검토 보고서의 전략 A에 가까움)
 주의: 이 세션의 GitHub 권한은 gmdjlee/cgs만 포함. 새 저장소는 창업자가 만들거나 권한을 추가해야 함.

## R2 투자 전략과 펀드 구조
Q05 조직 원형 (HF-REF-08 표 6-3)
 A 단일 매니저 펀더멘털 (TCI·엘리엇형)  B 시스템·퀀트 (르네상스·투시그마·AQR형)  C 멀티매니저 플랫폼 (밀레니엄·시타델형)  D 매크로 (브리지워터형)  E 하이브리드: 펀더멘털 + 퀀트 (D.E. Shaw형)
 권장 원칙: 검증 가능한 단일 핵심 전략 (A 또는 B). C는 설립 단계 모델로 부적합 (HF-REF-03 §2.1). 도구 질문에는 A, B, C, E를 넣고 D는 Other로 선택.
 영향: Q06, Q11, Q18, Q25, 로스터 조건부 에이전트
Q06 핵심 전략 (HF-REF-03 표 2-1)
 A 주식 롱숏  B 롱바이어스드  C 이벤트 드리븐·메자닌·공모주  D 퀀트·상대가치  E 매크로·픽스드인컴
 권장안 없음(창업자 역량). 사실: 롱숏은 공매도 잔고관리 전산 의무(HF-REF-06 §4.4), C는 비시장성 자산 50% 초과 시 개방형 불가(HF-REF-06 표 4-3), 고회전 전략은 증권거래세 0.20% 부담(HF-REF-06 §4.6). 롱바이어스드는 2025년 수익률이 시장 상승 영향이 커서 하락장 방어력 입증 필요 (HF-REF-02 §1.3).
Q07 관할권과 펀드 구조 (HF-REF-03 표 2-2, §2.2)
 A 국내 일반 사모펀드만  B 국내로 시작, 해외 자금 확인 후 케이맨 마스터-피더 추가  [권장: HF-REF-03 §2.2]  C 처음부터 국내 + 케이맨 병행  D 미국 onshore LP + 케이맨 (해외 중심)  E 싱가포르·홍콩 거점 (MAS·SFC 인가 별도)
Q08 목표 투자자 (복수 선택, HF-REF-03 표 2-3)
 A 국내 고액자산가 (증권사 PB·WM 채널)  B 국내 법인·전문투자자 (직접 영업)  C 국내 기관 (연기금·공제회·보험)  D 시드·앵커 투자자  E 해외 기관·패밀리오피스
 사실: 일반투자자 49인 이하, 개인 최소 3억원 (HF-REF-06 표 4-3). 도구 질문에는 A-D, E는 Other.

## R3 조직 설계
Q09 설계·구현할 조직 규모 (HF-REF-08 표 6-2)
 A 1단계 설립기 조직만 (에이전트 약 10~13개)  B 2단계 성장기까지 (약 22~27개)  C 3단계 기관화 표준 조직 전체 (약 24~31개)
 D 3단계 표준 조직도를 설계하고, 1단계 필수 역할부터 구현한 뒤 단계별로 활성화  [권장: '최상의 표준 조직' 목표를 설계로 충족하고, 쓰지 않는 에이전트를 먼저 만들지 않음. R-06]
 수치는 설계 추정치(design-spec §3).
Q10 통제 기능의 보고 라인 (HF-REF-08 §6.2 핵심, HF-REF-06 §4.5)
 A CRO·CCO 모두 대표이사 직보 (보고서 조직도)  B CRO·CCO 모두 이사회(감사) 직보  C CRO는 대표이사, CCO는 이사회 직보  D 소규모 겸직: 준법감시인이 위험관리책임자 겸직 (법률 검토 전제)
 권장: Q03=A/C/D이면 A, Q03=B(대표이사 겸 CIO)이면 B 또는 C. 이유: 리스크가 CIO에게 보고하면 안 됨.
Q11 프런트 오피스 세분화 기준 (Q05에 따름)
 A 섹터별 애널리스트  B 투자 과정 기능별 (발굴→분석→포트폴리오→실행)  C 전략별 운용팀(pod)  D 자산군별 (주식·채권·파생)  E 최소 구성 (PM 1 + 범용 애널리스트 1)
 권장: 1단계는 E, 성장에 따라 A(펀더멘털) 또는 B(퀀트). research-analyst 인스턴스 수를 결정.
Q12 지배구조와 지분 구조 (HF-REF-17 표 9-5, HF-REF-18 표 10-1, HF-REF-11 §7.7)
 A 창업자 단독 지배  B 공동 창업자 + 주주간 계약  C 시드·전략적 투자자 참여 (수익 공유 15~30% 또는 지분 10~25%, HF-REF-11 §7.7)  D 집행위원회형 집단 경영 (D.E. Shaw형, HF-REF-16 §9.3)
 권장안 없음. 모든 경우 주주간 계약·핵심 인력 조항·승계 계획 문서화 필요 (HF-REF-18 표 10-1). governance-secretary 활성화 시점을 결정.

## R4 통제 체계
Q13 통제 차단 방식 (구현 강제력)
 A 훅 기반 강제 차단: 보호 경로(한도 설정·규정·대외 문서) 변경과 단계 전환은 CRO·CCO 승인 기록이 있어야 통과  [권장: F-03, F-08]
 B 에이전트 판정 + 사람 최종 승인 (현재 CCGS 방식, 프롬프트 지시에 의존)
 C 모든 게이트 권고, 창업자가 최종 결정
 D 트랙별 차등: 설립 단계 권고, 운영 단계 강제 차단
Q14 통제 좌석(CRO·CCO) 생략 허용 범위
 A 생략 불가: 모든 게이트에 고정 참여, review_mode·team.size·workflow 설정의 영향을 받지 않음  [권장: F-04, F-05, F-06]
 B 운영 단계(실자본 관련) 게이트에서만 필수
 C full 모드에서만 필수
 D 생략 가능하되 생략마다 창업자 승인과 사유 기록
Q15 손실·익스포저 한도의 초기값 설정 방식 (HF-REF-09 §7.2 표 7-1)
 A 창업자가 수치를 직접 정함
 B CRO 에이전트가 전략·보고서 기준으로 초안을 만들고 창업자가 승인  [권장]
 C 멀티매니저 참고값(5% 손실 시 자본 축소, 7.5% 시 퇴출, HF-REF-08 §6.4)에서 출발해 조정
 D 법정 한도(레버리지 순자산 400%, HF-REF-06 표 4-3)만 먼저 적용, 내부 한도는 운용 개시 전에 결정
 모든 한도는 설정 파일(데이터)로 관리 (coding-standards: data-driven).
Q16 검토 강도 (modes.review_mode)
 A full: 모든 게이트 실행  B lean: 단계 전환 게이트만 (CCGS 기본값)  C solo: 게이트 생략  D 차등: 설립·통제 산출물은 full, 일상 리서치는 lean  [권장]
 주의: Q14=A이면 어떤 모드에서도 CRO·CCO 좌석은 실행됨.

## R5 공정 설계
Q17 수명 주기 구성 (workflow-catalog.yaml 대체)
 A 단일 단계축: 설립 8단계(S1~S8) → 성장 3단계(G1~G3), 투자 순환은 아이디어 단위 반복 공정  [권장: project.stage 단일값 구조 유지, /help·/gate-check 표만 교체 F-11]
 B 설립 트랙과 운용 트랙을 두 단계값으로 동시 관리 (트랙 차원 확장 필요)
 C 설립 트랙만 관리, 투자 운용은 도구 밖에서 수행
 D CCGS 7단계 이름만 바꿔 유지
Q18 투자 의사결정 기구 (HF-REF-09 §7.1)
 A CIO 단독 결정 + 의사결정 기록  B 투자위원회 합의 + 회의록  [권장: 운영 실사에서 투자 규율 입증 자료]  C PM 재량 + 중앙 리스크 한도 (멀티매니저형)  D 시스템 신호 + 모델 거버넌스 위원회 (퀀트형)
Q19 투자 메모 표준 깊이
 A 전체형: 8개 섹션 + CRO·CCO·퀀트 검토 (모든 포지션)
 B 표준형: 5개 섹션, 포지션 규모·위험 예산 임계치를 넘으면 전문 검토  [권장: 1단계 인력 규모에 맞춤]
 C 1쪽 메모, 전문 검토 없음 (인력 증가 후 강화)
 D 당분간 메모 스킬 없이 투자위원회 회의록으로 대체
Q20 전략 검증(모의 운용) 판정 기준
 A 정량 자동 판정 (샤프 지수·최대 손실폭·적중률 임계치)
 B 정성 판정 (PM 판단 + 투자위원회 표결)
 C 2단계: 정량 선별 후 투자위원회 검토  [권장: HF-REF-18 표 10-1 '비용을 반영한 백테스트 또는 과거 운용 기록', HF-REF-06 §4.6 거래세 반영]
 D 모의 운용 생략, 소규모 실자본 + 손절 한도로 바로 시작

## R6 우선순위
Q21 조직 운영 원칙 벤치마크 (복수 선택, HF-REF-16 표 9-4, HF-REF-17 표 9-5)
 A 수치화된 손실 규칙의 예외 없는 집행 (밀레니엄)  B 원칙 문서화와 극단적 투명성 (브리지워터)  C 연구 중심 집단 경영 (D.E. Shaw)  D 용량 통제와 규모 억제 (르네상스·시타델)  E 연구 공개를 통한 신뢰 확보 (AQR)
 권장: A + D (표 9-5의 첫 두 성공 요인). 도구 질문에는 A-D, E는 Other.
Q22 먼저 만들 신규 스킬 묶음 (복수 선택)
 A 설립·규정: 사업계획서, 규정집, 책무구조도, 등록 점검  B 투자 공정: 투자 메모, 투자위원회 검토, 사후 검토  C 리스크: 한도 설정·점검, 스트레스 테스트, 손실 규칙  D 컴플라이언스: 사전 점검 기록, 규제 보고 일정, 개인 매매·이해상충  E IR·운영: DDQ, 월간 보고서, 투자자 서신, 기준가 검증
 권장: Q01=D이면 A + D 먼저. 도구 질문에는 A-D, E는 Other.
Q23 첫 마일스톤
 A 통제 척추 (CRO·CCO + 한도 레지스트리 + 규제 일정)  B 투자 척추 (CIO·PM·애널리스트 + 메모 + 투자위원회)  C 설립 패키지 (사업계획서·규정집·책무구조도 초안)
 D 수직 단면: 아이디어 1건이 발굴→분석→투자위원회→사전 점검→사후 검토를 통과하고, 설립 단계 1개가 게이트를 통과  [권장, 단 Q01=A이면 C]
Q24 투자자 대면 도구
 A 사무관리회사의 표준 투자자 포털 사용  [권장: 차별화 원천이 아닌 영역은 구매, HF-REF-12 §7.8]  B 자체 투자자 포털 구축  C 정적 웹사이트 + PDF·이메일 보고  D 첫 펀드 설정 후 결정
 영향: 포털 관련 템플릿 9개 (CONDITIONAL investor-portal)
